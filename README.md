# Silver Rush 3D

لعبة ركض أصلية مبنية باستخدام Babylon.js وTypeScript strict وVite. مستودع العمل الوحيد: `storeqn/pepsiman-3d-web`.

**الحالة: مرحلة أولى قابلة للتطوير، وليست اللعبة النهائية ذات المراحل الخمس أو الجودة الفنية النهائية.** الشخصية والمدينة أصول إجرائية مؤقتة، مع إظهار ذلك داخل الواجهة. لا توجد أصول أو شعارات أو أصوات من Pepsiman أو Pepsi.

## التشغيل

يتطلب Node.js 22.12+ أو 24 وnpm ومتصفحاً يدعم WebGL2.

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

للاختبارات في المتصفح:

```sh
npx playwright install --with-deps chromium
npm run test:e2e
```

لبيئات الحاويات التي تمنع تعداد واجهات الشبكة:

```sh
npm run dev -- --host 127.0.0.1
```

## ما يمكن لعبه الآن

- مرحلة Downtown Rush بطول 2400 متر، نحو 193 ثانية من وقت المحاكاة، بداية ونهاية وحالات فوز وخسارة وإعادة محاولة.
- ركض تلقائي وحركة جانبية حرة، قفز وانزلاق، ثلاثة فرص مع حصانة مؤقتة بعد الاصطدام.
- حواجز منخفضة وعوارض علوية وسيارات متوقفة، وحلقات طاقة أصلية ونقاط.
- مدينة مؤقتة ذات أرصفة ومبانٍ وواجهات زجاجية ومحلات وأشجار وإنارة وممرات مشاة، مع إعادة تدوير ثمانية مقاطع.
- شخصية فضية وزرقاء بمفاصل إجرائية وحركات ركض وقفز وانزلاق. ليست GLB ولا Rig فني نهائي.
- PBR وخامة أسفلت مولدة وانعكاس بيئي محلي وظل الشخصية وضباب وتعديل دقة تلقائي اختياري.
- قوائم عربية RTL، تعليمات، إعدادات جودة وصوت، أفضل نتيجة وحفظ إكمال المرحلة في localStorage.
- أصوات وموسيقى بسيطة مولّدة برمجياً، وليست إنتاجاً موسيقياً نهائياً.
- PWA وملف manifest وأيقونات وService Worker مولّد أثناء البناء.
- المراحل الأربع التالية معروضة باعتبارها قيد التطوير، ولا تدّعي الواجهة أنها جاهزة.

## تنظيم الأنظمة

| النظام                                             | الملف                                             |
| -------------------------------------------------- | ------------------------------------------------- |
| دورة اللعبة والحالات والنتائج                      | `src/core/game.ts`                                |
| الحركة والاصطدامات وتوليد التحديات وFixed timestep | `src/core/simulation.ts`                          |
| الشخصية والحركة الإجرائية                          | `src/world/character.ts`                          |
| بناء المدينة والبث وتجمعات إعادة الاستخدام         | `src/world/world.ts`                              |
| خامات PBR                                          | `src/world/materials.ts`                          |
| التحكم / الكاميرا / الصوت                          | `src/systems/input.ts` / `camera.ts` / `audio.ts` |
| القوائم / الحفظ / الجودة                           | `src/systems/ui.ts` / `save.ts` / `quality.ts`    |

يعمل المنطق بخطوة 1/60 ثانية مع حد أقصى للتعويض بعد التأخير. تُدمج هندسة المدينة الثابتة حسب الخامة لتقليل أوامر الرسم، ويعاد استعمال العقبات والمقاطع، ويوجد LOD لإخفاء أوراق الأشجار البعيدة. **لم يُنفذ GPU instancing أو LOD شامل لكل الأصول بعد.** الكاميرا مقيدة داخل ممر الطريق الحالي؛ لا يوجد حل عام لتصادم الكاميرا مع بيئات مستقبلية.

## Cloudflare Pages

أنشئ مشروع Pages واربط **هذا المستودع فقط** ثم اختر فرع التطوير لمعاينة المرحلة الأولى، أو ادمجه لاحقاً حسب قرارك:

- Framework preset: Vite أو None.
- Build command: `npm run build`.
- Build output directory: `dist`.
- Node version: `22` أو `24`.
- Root directory: جذر المستودع.

الأصول تستخدم مسارات من جذر النطاق، وهي مناسبة لنطاق Cloudflare Pages. النشر تحت مسار فرعي مثل GitHub Pages يحتاج تعديل base ومسارات PWA؛ لم يُعتمد في هذه النسخة. لا يحتاج البناء مفاتيح سرية أو خادماً خلفياً. **تجهيز الملفات لا يعني أن نشر Cloudflare قد تم.**

## PWA والتحديث

الـService Worker يعمل في بناء الإنتاج فقط، على HTTPS أو localhost. عند التثبيت الأول يُخزّن shell وجميع حزم اللعبة وصور البيئة محلياً. يلزم اتصال أول مكتمل قبل العمل دون إنترنت. كل بناء ينتج اسم cache جديداً. التحديث ينتظر انتهاء الجلسات القديمة، ولا يستخدم skipWaiting كي لا يبدّل موارد اللعبة أثناء اللعب. يغلق المستخدم نوافذ اللعبة ثم يعيد فتحها لتطبيق التحديث. تحذف اللعبة caches السابقة ذات بادئتها فقط.

- iPhone: Safari ← مشاركة ← إضافة إلى الشاشة الرئيسية.
- Android / الكمبيوتر: تثبيت من قائمة المتصفح عند توفر الدعم.
- رفض التخزين المحلي لا يمنع اللعب، لكنه يمنع الاحتفاظ بالنتيجة.
